# Plan: Implement Movie-Genre Many-to-Many Relationship

## 1. Overview

Establish a many-to-many relationship between `Movie` and `Genre` entities using a join table `MovieGenre`. This enables movies to have multiple genres and genres to contain multiple movies. Includes full CRUD with role-based authorization.

## 3. Architecture Decisions

### 3.1 Relationship Type
- **Explicit join entity** (`MovieGenre`) rather than EF Core implicit many-to-many
- Reason: Need `IsActive` for soft-delete, `CreatedAt` for audit, and potential future fields (e.g., `IsPrimaryGenre`)

### 3.2 Authorization
- **Public read**: Anyone can see movie-genre associations
- **Admin write**: Only admins can create/delete links
- Leverages existing JWT `[Authorize(Roles = "Admin")]` infrastructure

### 3.3 Data Integrity
- **Unique constraint** on `(MovieId, GenreId)` prevents duplicates
- **Cascade delete** on both FKs (deleting a movie or genre removes its associations)

### Step 5: Create Service Implementation
**New file:** `Services/MovieGenreService.cs`

Key logic:
- **Create**: Verify movie exists, verify genre exists, check `ExistsAsync()` to prevent duplicates, create link
- **GetByMovieId**: Query `MovieGenres` where `MovieId == id`, include `Genre`, return mapped DTOs
- **GetByGenreId**: Query `MovieGenres` where `GenreId == id`, include `Movie`, return mapped DTOs
- **GetMovieWithGenres**: Get movie by ID, then query genres through join table, return aggregation DTO
- **GetGenreWithMovies**: Get genre by ID, then query movies through join table, return aggregation DTO
- Use `AsNoTracking()` for read operations
- Use `Include()` for eager loading navigation properties
- Return standardized response DTOs (Success, Message, Data)
